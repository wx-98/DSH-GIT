# Proposal

## Why

Git 插件已经能在右侧栏看分支、变更、历史，并在会话头部显示分支芯片，但用户实际使用后提出四个落差，且都能在本仓库找到根因：

1. **提交图只有蓝色、无法区分。** 泳道颜色按「列槽位」分配（`tools/graph-lanes.mjs` 的 `allocColor`），而本仓库历史是线性的，只有一列，于是整条图恒为调色板第 0 色（蓝）。用户看不出「哪条线属于哪个分支」，也无法在读图时区分主线与侧支。同时当前实现按列上色而非按分支上色，分支被回收复用时颜色还会换人。
2. **头部芯片字体突兀。** 芯片分支名硬编码 `font-family: var(--dsh-font-mono, monospace)`（`client.js` 的 `.dg-chip-branch`），而会话头部其它元素（`PTC 模式`、`3 个子智能体` 等）用的是宿主正文字体，等宽字体在标题栏里显眼且不协调。
3. **顶部只能看分支、不能切分支。** 芯片弹层是只读摘要；切换分支必须去面板「历史」页的下拉框，而那个下拉框改的是**日志的 ref 过滤**，不是 `checkout`——用户以为切了分支其实没切。Host 早有 `POST /git/checkout`，但没有任何入口调用它。
4. **功能密度与 IDEA 差距大。** 缺少 IDEA 源码管理里最常用的：变更按目录树折叠、每文件 +/- 行数、按 hunk 暂存/取消暂存、提交 amend、分支创建/删除、stash、历史过滤。没有这些，面板只能看不能用。

这些是同一组「把 Git 面板从可看做到可用」的需求，适合一次变更统一收口。

## What Changes

**A. 提交图可辨识（对应问题 1）**
- 颜色按**分支生命线**分配：一条分支线从出现到消失保持同一颜色，分支结束才释放颜色；同一时刻相邻/并存的泳道不共享颜色。
- 新增**当前分支高亮**：HEAD 所在列使用强调色（并给 HEAD 提交加大圆点 + 环形描边），其余分支用常规调色板。
- 分支首行可以带分支名胶囊（已有的 ref 胶囊继续保留），让「哪条线是谁」一眼可读。
- 保持列号跨行稳定（不左移）；缩小时不丢线（当前 `GRAPH_MAX_LANES=10` 截断时给出的提示）。

**B. 头部芯片排版（对应问题 2）**
- 去掉等宽字体，字号/字重/行高与宿主头部其它胶囊一致（`font: inherit`，12px/18px），只保留 `tabular-nums`。
- 芯片内元素间距、圆点尺寸与宿主头部胶囊对齐；图标改为与宿主头部图标同尺寸。
- 深/浅主题下对照头部其它元素做一次视觉回归。

**C. 顶部分支切换与分支管理（对应问题 3）**
- 芯片弹层升级为**分支面板**：顶部「当前分支」+ 下方「切换分支」列表（本地分支、远端分支分组，显示 ahead/behind 与是否当前分支），点击即 `git checkout`。
- 切换失败（工作区脏、冲突、无权限）用弹层内错误条展示 git stderr 首行，不静默失败。
- 面板「历史」页的分支过滤与**切换分支**彻底分开：过滤只影响日志，切换是独立动作（并给出「已切到 xxx」反馈）。
- 新增分支创建、删除、重命名入口（创建= `git switch -c`，删除= `git branch -d/-D` 带确认，重命名= `git branch -m`）。

**D. IDEA 对齐 Phase 1（对应问题 4）**
- 变更列表改为**目录树**：按路径层级折叠/展开，每行显示文件名 + 状态 + `+N/-N`；分组仍在（已暂存/变更/未跟踪/冲突）。
- **Hunk 级暂存/取消暂存**：diff 视图内每个 hunk 有「暂存此块 / 取消暂存此块」，Host 端用 `git apply --cached` 应用单块补丁。
- **提交增强**：amend 上一个提交、提交信息历史（本地保存最近 10 条）、`--all` 显式开关。
- **Stash**：列表、创建、应用、弹出、删除。
- **历史过滤**：按提交信息/作者过滤，按路径过滤（`git log -- <path>`），过滤条件在页面上可见且可清除。
- 所有写操作沿用现有约定：连接栅栏、串行队列、契约化错误码、失败有可见反馈。

**明确不在本次范围**（避免范围失控，留待后续变更）：
- `fetch` / `pull` / `push` 等网络操作（需要凭据与远端交互设计）
- 三方冲突解决界面、rebase、cherry-pick、submodule
- blame / 文件历史 / 并排（side-by-side）diff

## Capabilities

### New Capabilities
- `source-control-panel`: 右侧栏源码管理面板的行为——变更列表（配色、目录树、每文件增删行）、暂存/取消暂存/放弃（含 hunk 级）、提交与 amend、diff 视图。
- `commit-history`: 历史视图的行为——提交列表、提交图（泳道配色、HEAD 高亮、列稳定）、提交详情与逐文件 diff、日志过滤。
- `branch-management`: 分支相关行为——会话头部芯片（排版与宿主一致、实时状态、弹层）、分支切换、创建/删除/重命名，以及失败反馈。
- `git-host-api`: Host 侧 `/git/*` 契约——路由集合（含本次新增）、路径与参数校验、错误码映射、连接栅栏、写操作串行化。

### Modified Capabilities
（无。仓库 `openspec/specs/` 目前为空，本次变更是这些能力的首个基线。）

## Impact

- **代码**：`client.js`（芯片、弹层、变更树、diff hunk 操作、提交框、历史过滤、提交图渲染）、`index.js`（新增路由与参数校验）、`lib/git.js`（新增 git 操作与解析：numstat 汇总、patch 应用、amend、分支增删改、stash、log 过滤）、`tools/graph-lanes.mjs`（按分支分配颜色）。
- **测试**：`test/host.test.js`、`test/client.test.js`、`test/graph-lanes.test.js` 需扩充；新增 hunk 级暂存与分支/ stash 操作的端到端用例。
- **契约与文档**：`docs/contract.md` 需登记新路由与新字段；`docs/verification.md` 增加本轮浏览器验证记录；`README.md` 更新能力清单与截图。
- **兼容性**：现有 `/git/*` 路由保持向后兼容（只新增不改签名）；插件版本升到 0.3.0；无新增运行时依赖、无构建步骤。
- **风险**：`git apply --cached` 的补丁上下文要精确（行号偏移/空白），需要为 CRLF 仓库与「已部分暂存」场景补测试；分支禁用当前分支删除；工作区脏时切换分支要给出可读错误而不是 422 壳。
