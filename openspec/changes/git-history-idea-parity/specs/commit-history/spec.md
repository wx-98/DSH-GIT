# Spec Delta

## MODIFIED Requirements

### Requirement: 历史列表可过滤

历史视图 SHALL 支持按提交信息、作者、路径与日期范围过滤提交，过滤条件 MUST 在界面上可见并可一键清除；清除后 MUST 恢复完整列表。日期范围 MUST 以本地时区解释，并与其他过滤条件同时生效。

#### Scenario: 按提交信息过滤
- **WHEN** 用户在过滤框输入 `fix`
- **THEN** 列表只显示提交信息中包含 `fix` 的提交，并显示「已过滤」提示与清除入口

#### Scenario: 清除过滤
- **WHEN** 用户点击清除过滤
- **THEN** 列表恢复为完整的提交历史

#### Scenario: 按日期范围过滤
- **WHEN** 用户把起始日期设为 2026-10-01、结束日期设为 2026-10-31
- **THEN** 列表只显示这两个日期之间（含边界）的提交，其他过滤条件仍然生效

#### Scenario: 日期范围内没有提交
- **WHEN** 所选日期区间内没有任何提交
- **THEN** 列表显示「没有匹配的提交」空状态，而不是空白区域

## ADDED Requirements

### Requirement: 分支树与提交列表的双栏布局

历史视图 SHALL 提供左侧分支树（HEAD / 本地 / 远端三组）与右侧提交列表；选择分支树中的某项 MUST 只把该分支设为日志范围而不改变 HEAD；MUST 提供回到「全部」的复位项；面板宽度不足时分支树 MUST 可折叠而不是压缩列表。

#### Scenario: 选择分支过滤日志
- **WHEN** 用户在分支树点击 `feature/x`
- **THEN** 提交列表只显示该分支可达的提交，HEAD 不变，列表顶部显示当前范围

#### Scenario: 复位到全部
- **WHEN** 用户在分支树选择「全部」
- **THEN** 列表恢复为完整历史

#### Scenario: 窄面板折叠分支树
- **WHEN** 面板宽度不足以同时显示分支树与列表
- **THEN** 分支树折叠为可展开的入口，提交列表保持可读宽度

### Requirement: 提交行的列布局与合并提交样式

每条提交 SHALL 以列式布局显示：提交图、提交主题（含 refs 胶囊）、作者、日期与短哈希；refs 胶囊 MUST 区分本地分支、远端分支与 HEAD；合并提交（父提交多于一个）MUST 使用弱化样式（斜体 + 次要色）；HEAD 行 MUST 保持强调高亮。

#### Scenario: 合并提交弱化显示
- **WHEN** 历史中出现一个双父合并提交
- **THEN** 该行主题使用斜体与次要色，与普通提交可区分

#### Scenario: refs 胶囊区分类型
- **WHEN** 某行同时带有 `HEAD -> main`、`origin/main` 与一个本地分支胶囊
- **THEN** 三种胶囊在颜色或图标上可区分

#### Scenario: 日期与哈希列
- **WHEN** 用户浏览列表
- **THEN** 每行显示形如 `2026-10-26 17:59` 的绝对日期与 7 位短哈希，悬停日期显示相对时间

### Requirement: 提交列表的键盘导航

历史列表 SHALL 支持 ↑/↓ 在提交行之间移动选中项，Enter MUST 打开当前选中提交的详情，并保证移动时列表滚动使选中行可见。

#### Scenario: 键盘选择提交
- **WHEN** 用户连续按 ↓ 三次后按 Enter
- **THEN** 选中项向下移动三行，并打开该提交的详情视图
